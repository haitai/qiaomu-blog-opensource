# 乔木简阅 · 蓝图注 —— 主题设计锚

适用范围：仅约束微信公众号导出主题 `qiaomu-clean-reading`（「乔木简阅」）的落地样式，
对应 `lib/wechat-themes.ts` 中该主题的 `buildEditorialCss` 配置。不改动根目录产品基线 DESIGN.md。
来源：2026-09-03 四方向预览中用户选定的 B「蓝图注」（视觉冒险度 7 / 动效 1 / 信息密度 6），
证据见同目录 `selection.json`，样机见 `index.html` 的 `.dir-b`。

## 1. 视觉氛围

一份产品团队的内部研读简报，而不是杂志或营销页。冷白纸面（`#fbfdfe`）上只有两种信号：
墨色文字承担内容，深青（`#0f7285`）承担结构与重点。装饰被压缩到只剩 1px 发线和浅青高亮，
读者遮住颜色也能靠 H2 通栏发线、引用双发线、代码纸面这些结构差异导航。
DNA：Mintlify 的清晰度优先（16px 正文、400/500/600 三档字重、等宽字体承担技术语义）
× Resend 的冷色细边线层级（用发线而不是灰框或重阴影分区，代码块是一等视觉组件）。

## 2. 色板角色

| 角色 | 色值 | 用途 |
|---|---|---|
| 纸面 | `#fbfdfe` | 文章底与全局底，冷白不刺眼 |
| 正文 | `#25343f` | 段落、列表、表格正文 |
| 标题 | `#142530` | 文章标题与 H2 |
| 主强调 | `#0f7285` | H3、链接、列表标记 |
| 浅高亮 | `#dff0f4` | strong 底色 |
| 高亮上文字 | `#0b5b6b` | strong、行内 code |
| 发线 | `#c3d9e0` | H2 底线、引用双发线、hr |
| 次文 | `#6b7f8c` | 图注、meta |
| 代码纸面 | `#f2f8fa` | 代码块容器、行内 code 底 |
| 代码顶条 | `#e2edf1` | mac 三色点顶条 |
| 代码边框 | `#d3e2e8` | 代码块 1px 描边 |
| 代码正文 | `#2a3b46` | 代码字符，行号 `#9db4bd` |

禁用：纯黑 `#000`、渐变、暖色系、第二强调色。

## 3. 排版规则

- 字体：中文系统无衬线栈（PingFang SC / Hiragino Sans GB / Microsoft YaHei / Noto Sans CJK SC），
  代码走等宽栈；不引入远程字体，不照搬 Inter。
- 字重只允许 400 / 500 / 600；中文 CJK 无真实 650+ 字重，禁止用伪粗体撑层级。
- 正文 16px / 400 / 行高 1.8 / 字距 0 / 左对齐；段落间距靠 margin 节奏，不空行堆砌。
- H2：20px / 600 / `#142530`，左对齐，行高 1.3。
- H3：16px / 600 / `#0f7285`，字距 0.02em，左对齐。
- 图注 13px / 次文色 / 居中。

## 4. 组件样式

- **H2**：纯文本原生 h2，`padding-bottom: 10px` + `border-bottom: 1px solid #c3d9e0` 通栏发线收尾。
  不注入编号、span、伪元素、左侧竖线、背景或渐变。
- **H3**：纯文本原生 h3，深青文字领起小节，无编号。
- **strong**：浅青底（`#dff0f4`）+ 深青字（`#0b5b6b`）+ `padding: 0 4px` + 3px 圆角，
  不纯靠字重，小屏识别速度优先。
- **a**：深青 + 下划线 + `text-underline-offset: 3px`，`word-break: break-all` 处理长 URL。
- **blockquote**：上下各 1px 发线的三明治，`padding: 14px 2px`，无左竖线、无圆角、无背景图。
- **代码块**：`#f2f8fa` 容器 + `#e2edf1` mac 顶条 + `#d3e2e8` 边框 + `#2a3b46` 正文，
  行号 `#9db4bd`；8px 圆角与自动换行（`pre-wrap` / `overflow-wrap: anywhere`）来自全局兼容层，不回退。
- **img**：圆角 8px 封顶；**hr**：1px 实色发线，不用渐变。
- **行内 code**：`#f2f8fa` 底 + 1px `#e2edf1` 细边 + `#0b5b6b` 字，等宽字体承担技术语义。

## 5. 布局原则

- 文章容器 `padding: 18px 8px 32px`，移动端 8px 页边距是硬约束，桌面端 `max-width: 680px` 居中。
- 8px 基准网格：组件内外间距都落在 8 的倍数或其 em 等价节奏上。
- 单栏通读，H2 发线通栏贯穿，是小屏上零成本的章节导航。

## 6. 深度层级

全部用发线与底色差表达，禁止投影堆叠：
L0 纸面 → L1 1px 发线分区（H2 底线、引用双发线、hr）→ L2 浅青填充（strong、表格头 `#dff0f4`）
→ L3 代码纸面（`#f2f8fa` + 1px 边框 + 顶条分层）。没有 L4。

## 7. Do / Don't

**Do**
- 用 1px 冷色发线建立一切分区；用 `#dff0f4` 承担唯一的高亮语义。
- 保持 H2/H3 为纯文本原生标签，样式只写在选择器自身。
- 代码块保持浅色纸面 + mac 三色点 + 行号换行，做成一等视觉组件。

**Don't**
- 不用渐变、背景图、阴影、左侧竖线、编号、伪元素、超大圆角（>8px）。
- 不用纯黑、不用字重超过 600、不用斜体、不用宋体等衬线标题。
- 不为「新颖」发明装饰语法；任何元素先回答「它降低了哪一层理解成本」。

## 8. 响应式

主战场是 375px 微信竖屏：8px 页边距 + 通栏发线 + 左对齐即全部适配策略；
长 URL、长代码行靠 `word-break: break-all` / `overflow-wrap: anywhere` 兜住，不允许横向溢出。
桌面端只是 680px 居中列，无第二套布局。

## 9. Motion 哲学

动效拨盘为 1：主题完全无动效。微信粘贴产物是静态内联样式，
节奏感由空间（margin 层级、发线位置）承担，不由时间承担。
